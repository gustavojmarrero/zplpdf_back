# BE00–BE01: observabilidad v1

Integración: importar `ProductObservabilityModule` en AppModule; el coordinador integra su registro. Rutas bajo el prefijo global `/api`.

- `GET /users/me/features`: FirebaseAuthGuard; siete capacidades, plan obtenido del perfil servidor, flags apagados por defecto. `PRODUCT_FEATURE_FLAGS` es JSON de configuración exclusivamente servidor; cada entrada requiere enabled, killSwitch, owner, updatedAt, version, allowedPlans, rolloutPercent, experimentId y assignmentVersion. Asignación SHA-256 estable por cuenta/experimento/versión, nunca por parámetros web. Cambiar cohortes requiere nueva assignmentVersion. `assertFeatureAvailable` protege ingresos nuevos; apagar no borra trabajos existentes.
- `POST /product-events/web`: FirebaseAuthGuard, cuerpo `{sentAt,consentEpoch,sessionEpoch,consent:{analytics:true,version:"2026-09-17"},events:[...]}` de 1–20 eventos. Allowlist `feature_exposed`, `feature_interacted`; campos eventId UUIDv4/UUIDv5, schemaVersion=1, occurredAt UTC, featureId, featureVersion, surface y action opcional enum. Sin UID, plan, éxito, pagos, propiedades libres ni texto. AccountId y entorno proceden del servidor. sentAt es UTC; consentEpoch y sessionEpoch son UUIDv4 opacos declarados por cliente. Validarlos no prueba consentimiento histórico ni vinculación verificada de sesión. Exposición no implica activación.
- `GET /admin/observability/quality` y `/admin/observability/snapshots`: AdminAuthGuard. Devuelven missing_data/insufficient_data con valores null hasta disponer de agregación verificable; nunca inventan ceros.

Persistencia: provider `PRODUCT_OBSERVABILITY_FIRESTORE` que reutiliza `FirestoreService.getClient()` vía CacheModule; sin campos privados, cliente paralelo ni proyecto alternativo. `product_events` y `event_outbox` se escriben en una transacción, deduplicando SHA-256(accountId,eventId); hechos servidor además identidad semántica accountId/eventName/operationId. Exposición web se deduplica por accountId/featureId/featureVersion/surface/assignmentVersion/variant/día America/Merida; asignación y variante proceden exclusivamente del servidor. Los recibos conservan identidad/fingerprint incluso para entregas suprimidas por deduplicación semántica. Timestamps funcionales ISO UTC; expiresAt es Timestamp nativo para TTL de 90 días. Habilitar TTL fuera de este cambio para las colecciones de eventos, dedup y outbox; TTL no es borrado inmediato. La eliminación de cuenta debe barrer product_events, product_event_dedup, event_outbox y growth_assignments filtrando accountId antes de habilitar producción.

API interna: `ProductObservabilityService.recordServerEvent(input, transaction?)` valida eventos canónicos y obtiene plan del servidor; operationId identifica la operación semántica, eventId la entrega. Para atomicidad con negocio, usar una transacción del provider exportado, hacer primero todas las lecturas de negocio y llamar recordServerEvent antes de añadir escrituras de negocio. Si devuelve duplicate=true, no repetir efectos. Sin transaction abre su propia transacción: solo usar tras resultado duradero o para reconciliación, nunca afirmar atomicidad con una escritura previa. No llamar desde controladores web con payload del cliente. Éxitos canónicos no dependen de consentimiento web ni de GA4.

Outbox: `ProductEventOutboxService.dispatch(deliver, limit?)` reclama lease con token, recupera leases vencidos, entrega al consumidor explícito y hace ack condicional al token. Entrega al menos una vez: consumidor deduplica por event key; backoff exponencial, ocho intentos y estado dead recuperable mediante `retryDead`. No hay consumidor GA4, cron, red externa o despacho automático. La consulta usa solo availableAt con índice simple; ack/dead eliminan availableAt. Los snapshots no cuentan outbox como entrega analítica verificada.

Pendiente para habilitar: integración AppModule por coordinador, consumidor/agregador, TTL y borrado de cuenta, prueba con emulador/staging e índices según futuros agregados. No despliegue ni modificación de precios o pagos.

Valores v1: featureId = `packing_workflow | data_templates | self_service_api | pdf_preparation | folder_automation | direct_print | template_regression`; planes = `free | lite | pro | promax | enterprise`. `surface` = `dashboard | editor | history | admin | workspace | navigation | feature_page | onboarding | tour`. `action` = `open | start | cancel | help | retry`, obligatoria solo para `feature_interacted` y prohibida para exposición. `sentAt` y `occurredAt` web aceptan hasta siete días de retraso y cinco minutos de adelanto; featureVersion debe coincidir con el servidor. Respuesta HTTP 202: `{schemaVersion:1,results:[{eventId,key,duplicate}]}`; esquema inválido/flag no disponible = 400, colisión de eventId con contenido diferente = 409. La deduplicación conserva su garantía durante la retención de 90 días.

Hechos canónicos v1: `packing_export_succeeded`, `packing_reexport_succeeded`, `packing_reconcile_completed`, `template_saved`, `template_run_succeeded`, `api_job_succeeded`, `pdf_preparation_export_succeeded`, `folder_run_succeeded`, `print_job_acknowledged`, `print_confirmed`, `regression_run_completed`, `baseline_approved`. Un acuse del conector no autoriza emitir print_confirmed; la operación debe aportar evidencia física o confirmación manual identificada. No se incluyen pagos en esta API v1: conciliación financiera conserva su propia identidad semántica.

`ServerEventInput` exige eventId/operationId UUIDv4, schemaVersion=1, eventName, accountId, featureId, featureVersion, occurredAt UTC y source=`api|folder|print`; workflowId/jobId opcionales UUIDv4, durationMs/labelCount enteros no negativos, isSynthetic booleano. Roles admin y simulaciones se marcan sintéticos automáticamente. `PRODUCT_ENVIRONMENT` acepta development/test/staging/production y cae a NODE_ENV, después development. Los productores no envían PII ni contenido libre. El receptor de outbox recibe `(event, idempotencyKey)` y debe deduplicar antes de ejecutar efectos; el módulo solo marca delivered si la promesa se resuelve y el lease sigue vigente. Un timeout mayor a 60 segundos exige consumidor idempotente; no se garantiza entrega exactamente una vez.

Verificación local: pruebas unitarias/HTTP con Firestore transaccional simulado, sin conexión externa. El fake verifica rollback y orden lecturas/escrituras; no sustituye una prueba del SDK contra emulador/staging. La configuración desplegada de TTL/consumidores y la eliminación de cuenta siguen pendientes de integración. Este archivo cae bajo `docs/*` de .gitignore y debe incorporarse con `git add -f docs/growth/observability-contract.md`.

Asignación ITT: al evaluar una feature elegible, enabled y sin killSwitch, se crea transaccionalmente `growth_assignments/{SHA256(accountId,experimentId,assignmentVersion)}` antes de cualquier exposición y sin exigir consentimiento analítico. Campos accountId, experimentId, assignmentVersion, assignedAt ISO UTC, initiallyPaid, featureId, variant, plan, isSynthetic y environment. Primera escritura gana: ni assignedAt ni variante se sobrescriben al reevaluar/cambiar rollout; una cohorte nueva necesita assignmentVersion nueva. initiallyPaid significa plan inicial distinto de free, no evidencia de factura positiva, cortesía ni elegibilidad comercial reconciliada. Asignaciones quedan hasta borrado de cuenta/política experimental explícita; no aplicar TTL de eventos a ellas sin preservar asignación original.

Para UUIDv5 compartido entre pestañas, reenvíos de exposición en el mismo día/superficie/asignación aceptan occurredAt/sentAt/épocas diferentes sin multiplicar el evento. Interacciones mantienen timestamp exacto en su identidad. Cada cambio de día usa America/Merida, mientras todos los timestamps almacenados siguen UTC.
